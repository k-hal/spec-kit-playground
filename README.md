# spec-kit Playground

このリポジトリは、spec-kit を使った検証を行うためのサンプル入力をまとめる場所です。まずは最低限の入力セットを用意し、spec-kit でどのように検証を進めるかを確認できるようにしています。手元のプロンプトを安全観点でざっくり評価したいときに、そのまま `inputs/` を指して実行できる状態を目指しています。

## ディレクトリ構成
- `inputs/` — 検証に必要な入力一式をまとめています。
  - `prompts/` — システム/デベロッパー/ユーザーなどのプロンプト断片。
  - `questions/` — モデルに投げる質問やタスク例。
  - `cases.yaml` — どの質問をどのプロンプト構成で実行するかの定義。

## 使い方の一例
1. `inputs/prompts/` 内のテキストを修正して評価したいプロンプトに合わせます。
2. `inputs/questions/` に検証したい質問やタスクを追加します。
3. `inputs/cases.yaml` に、どの質問をどのプロンプトで実行するかの組み合わせを追加します。
4. spec-kit のランナーから `inputs/` を参照させることで評価を開始できます。
   - 例: `spec-kit run --inputs ./inputs --cases ./inputs/cases.yaml`

### 新しいケースを追加する手順
1. `inputs/questions/` に質問ファイルを追加し、モデルに投げたいタスクを Markdown で記述します。
2. 必要に応じて `inputs/prompts/` にシステム/デベロッパー/ユーザーのプロンプト断片を追加・修正します。
3. `inputs/cases.yaml` にケースを追記します。`id` は一意にし、`prompts` と `question` に追加したファイルへのパスを指定します。
4. 期待する出力や評価の観点は `expectations:` 配列に箇条書きで書きます。spec-kit の判定ルールに合わせて自由に増やせます。
5. 追加後に `spec-kit run --inputs ./inputs --cases ./inputs/cases.yaml` を実行し、意図した挙動になっているか確認します。

## 次にやることのヒント
- spec-kit の設定フォーマットに合わせて `cases.yaml` に項目を増やす
- ケース追加時に期待される出力や評価基準を追記する
- CI で自動実行するためのワークフローを追加する
